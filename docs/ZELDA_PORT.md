# Zelda 64: Half-Life

This mod puts Ocarina of Time's Link into GoldSrc. It ports his movement, camera, Z-targeting, sword combat, rolling, items, HUD, text boxes and music playback. The code follows the zeldaret/oot decomp (NTSC 1.0) as closely as GoldSrc allows. Every ported routine names its OoT original in a comment (`Player_Action_Roll`, `Camera_Battle1`, `Message_Decode`, ...).

> **No ROM-derived data is in this repository.** Out of the box, every asset is either from Half-Life or generated by the scripts in `tools/zelda`. Ripped OoT assets go into paths that `.gitignore` excludes (`zelda/sprites/oot/`, `zelda/sound/zelda/oot/*.wav`, music files under `zelda/music/`, `zelda/models/player/link/*.mdl`, `zelda/resource/zl_oot_messages.txt`). The game prefers those files whenever they exist.

## Building

### Windows (Visual Studio 2019 or later)

1. Open `projects/vs2019/projects.sln`.
2. Build **hldll** and **hl_cdll** (Release, Win32). The new `zl_*` sources and the vendored `external/` libraries (lazyusf2, psflib, zlib) are already in both projects.
3. Copy the `zelda` folder into your Half-Life install, so that you have `Half-Life/zelda/liblist.gam`.
4. Copy `hl.dll` to `Half-Life/zelda/dlls/` and `client.dll` to `Half-Life/zelda/cl_dlls/`.
   - By default the projects' post-build step copies to `game\mod`. Change that path (or the `$(HalfLifeDir)` / mod name settings) to point at `zelda` if you want the copies to happen automatically.
5. Music playback uses SDL2, which ships with the Steam version of Half-Life.
   - The client links against `lib/public/sdl2.lib`, which the stock SDK project already does.
   - To build without USF support, define `ZL_NO_USF`. `.wav` music still works.
6. Start the game with `hl.exe -game zelda +map zl_test`. Compile the test map first; see [Test map](#test-map).

### Linux

```sh
sudo apt install g++-multilib          # 32 bit toolchain
linux/build_zelda.sh                   # builds hl.so + client.so and copies them into zelda/dlls and zelda/cl_dlls
```

Then copy or symlink `zelda/` into your Half-Life directory.

## Controls

Link is played with the OoT pad layout. Every control is an ordinary bind, so a gamepad can be mapped later. `zelda/zl_binds.cfg` is executed from `default.cfg`.

| N64 | Command | Default key | Does |
|---|---|---|---|
| Stick | `+forward/+back/+moveleft/+moveright` | WASD | Camera relative movement. `CTRL` walks (half stick). |
| A | `+zbtn_a` | SPACE | Context action: roll, sidehop, backflip, jump attack, speak, check, open, climb, put away. |
| B | `+zbtn_b` | MOUSE1 | Sword. Combos, jump attack, spin attack by holding. |
| Z | `+zbtn_z` | MOUSE2 | Z-target. Hold, or toggle with `zl_ztoggle 1`. With nothing targeted it snaps the camera behind Link. Z + A: sidehop, backflip, or jump attack with the stick forward. |
| R | `+zbtn_r` | SHIFT | Shield. |
| C-left | `+zbtn_cleft` | Q | Item |
| C-down | `+zbtn_cdown` | R | Item |
| C-right | `+zbtn_cright` | F | Item |
| C-up | `+zbtn_cup` | TAB / MOUSE3 | First person look. |
| Mouse | – | – | Orbits the camera (`zl_cam_mouse 0` gives OoT's stick-only camera). |
| Start | `zl_inventory` | – | Prints the inventory. There is no subscreen yet. |

Equip items with `zl_equip <0|1|2> <item number>` (C-left, C-down, C-right; items 1 bow, 2 bombs, 3 hookshot, 4 longshot, 5 nuts). A Half-Life weapon you pick up goes onto the first empty C button. Pressing that button fires its primary attack.

### How the movement works

- **OoT timing.** OoT runs at 20 Hz, and `Actor_UpdatePos` moves an actor by `velocity × 1.5` per frame. `zl_shared.h` converts with `ZL_VEL`, `ZL_ACC` and `ZL_FRAMES`, using 1 OoT unit = 72/68 HL units (Link is 68 units tall in OoT and 72 in HL).
  - This gives the original numbers: run speed 6.0, acceleration 2.0, deceleration 1.5, gravity 1.0 per frame (about 635 u/s²) and terminal velocity 20.
- **Prediction.** `PMZ_Think` runs inside `PM_PlayerMove`, so the client predicts it.
  - Shared state lives in `fuser1` (facing yaw), `fuser4` (action timer), `iuser4` (action, sub-state, melee attack, combo, previous pad buttons) and `iuser3` (server flags: has target, talking, items...).
  - These fields are added to `clientdata_t` through `zelda/delta.lst`.
- **Camera relative input.** `cmd.viewangles` is the camera direction, not Link's. Link's facing is the separate `fuser1` and turns at OoT's rates (2000 binang per frame free, 4000 when Z-targeting).
  - The client camera owns the engine view angles. The server sets the player's `angles` from the facing.
- **Buttons.** The OoT buttons reuse unused `IN_*` bits (A = IN_JUMP, B = IN_ATTACK, Z = IN_ALT1, R = IN_DUCK, C = IN_ATTACK2 / IN_RELOAD / IN_RUN / IN_SCORE).
  - The server removes them from `pev->button`, so stock HL code never sees them. When a C button holds an HL weapon, it becomes IN_ATTACK.

### Damage

`ZL_HLDamageToHealth` converts HL damage into whole quarter hearts. Health is stored in OoT units (16 per heart) in `pev->health`. `TakeDamage` then applies OoT's rules:

- no damage while talking or during i-frames (20 frames after a hit, roll frames 8–18)
- frontal shield block
- double defense halves damage
- knockback and knockdown

Outgoing damage goes the other way through `ZL_OoTDamageToHL`:

| Attack | OoT damage |
|---|---|
| Sword | 1 / 2 / 4 |
| Jump attack, spin | ×2 |
| Big spin | ×4 |
| Arrow | 2 |
| Bomb | 4 |

## Sound table

Every sound Link makes is listed in `pm_shared/zl_sounds.h` with a Half-Life stand-in, the OoT `NA_SE_*` it replaces, and that sound's random pitch from OoT's SFX tables (`Audio_ComputeSfxFreqScale`). The random pitch applies to the stand-ins as well.

Each sound plays `sound/zelda/oot/<NA_SE name>.wav` when that file exists (made by `tools/zelda/extract_sfx.py`), else its Half-Life stand-in. `zl_oot_sounds 0` forces the stand-ins. The server decides this when the map loads and precaches only what it chose; the console prints how many of each.

Footsteps follow OoT's walk cycle (`func_8084029C`). Their frequency (0.9 to 1.1) and volume come from Link's speed, and `NA_SE_PL_WALK_GROUND` adds up to 16% random pitch on top.

## Assets from your own ROM

None of these files are committed. All of them are listed in `.gitignore`.

### Decomp setup

First, set up the decomp with your NTSC 1.0 ROM, in a checkout of zeldaret/oot:

```sh
cp baserom.z64 baseroms/ntsc-1.0/baserom.z64
make setup VERSION=ntsc-1.0
```

### HUD, font and text

```sh
python3 tools/zelda/rip_from_decomp.py --oot /path/to/oot --version ntsc-1.0
```

This writes:

- `zelda/sprites/oot/*.spr`: hearts, the magic bar, rupee and key icons, button and item icons, text box textures, the font, and its `zl_font.txt` widths.
- `zelda/resource/zl_oot_messages.txt`: the whole English message table with `{CODES}` converted, plus `ITEM_*` aliases for the item get messages.

The client prefers both over the generated stand-ins.

### Sound effects

```sh
python3 tools/zelda/extract_sfx.py --oot /path/to/oot
```

OoT has no sound effect files. Each `NA_SE_*` is a little program in the SFX sequence (`seq_0.prg.seq`) that plays instrument samples.

`extract_sfx.py` interprets those programs over the samples `make setup` extracted and writes 22 kHz WAVs into `zelda/sound/zelda/oot/`. It covers:

- notes, instruments, transposes, pitch slides, legato, loops
- voice clips with several takes: `NA_SE_VO_LI_SWORD_N` has four "Hup!"s, written as `NAME.wav`, `NAME_2.wav`, ... plus `variants.txt`. The game picks one at random, like OoT.

Envelopes, vibrato and filters are approximated or ignored. Sounds that loop until stopped are cut at `--max-seconds`.

`--all` renders every sound in the game. `convert_sfx.py` is still there if you'd rather convert your own recordings.

### Music

1. Drop `.miniusf` files and their `.usflib` (any OoT USF set) into `zelda/music/oot/`.
2. Test with `zmus_play music/oot/<file>.miniusf 1`.
3. Place `ambient_zmusic` entities in your maps.

The `length` and `fade` tags are honoured; a track loops unless flag 2 is set. A `.wav` works too.

### Link's model

```sh
python3 tools/zelda/make_link_model.py --oot /path/to/oot --studiomdl /path/to/studiomdl --preview
```

This converts adult Link from the decomp's extracted assets:

- **Skeleton:** `gLinkAdultSkel`, 21 limbs, becomes 21 bones.
- **Mesh:** each limb's near display list, run through a small F3DEX2 interpreter.
  - Vertices are skinned to whichever limb matrix was loaded when they were (OoT stitches joints by loading a few vertices under the parent's matrix).
  - The colour combiner's PRIMITIVE / ENVIRONMENT colours are baked into the textures. The tunic is Kokiri green; `--tunic goron|zora` changes it.
  - Mirrored texture axes are unrolled into double-size textures.
  - Faces drawn with culling off get a back face.
  - Environment-mapped (`G_TEXTURE_GEN`) parts become HL chrome.
- **Animations:** the `gPlayerAnim_*` the game uses, at 20 fps. `--all-anims` converts all 573.
  - Sequence names are the OoT names without `gPlayerAnim_`, cut to 31 characters.
- **Bodygroups:** the hands and sheath, following OoT's `gPlayerModelTypes`. The server switches them:
  - sword and shield in hand after attacking, until A "Put Away"
  - shield in hand while holding R
  - the bow or hookshot while aiming or Z-targeting with it
- **Skins:** eyes open / half / closed, which the server cycles to blink.

The output goes to `tools/zelda/build/link/` (SMD, BMP, QC, `preview.png`) and `zelda/models/player/link/link.mdl`. Both are git ignored.

To compile on Windows without `--studiomdl`, run `studiomdl link.qc` from the SDK's `utils/studiomdl` build, or use Crowbar. In single player the client draws Link with the model the server set, not the `model` userinfo key.

### Test map

`tools/zelda/make_test_map.py` writes `zelda/maps/zl_test.map`. Compile it with VHLT:

```sh
hlcsg zl_test && hlbsp zl_test && hlvis zl_test && hlrad zl_test
```

The room contains:

- climbable and unclimbable ledges
- a pit with a hookshot wall
- zombies and headcrabs
- a scientist and a guard
- a chest, signs, a door, crates and items
- an `ambient_zmusic`
